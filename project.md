# Polaris (репозиторий: polaris-pl) — project spec (v1)

Статус: черновик спецификации. Источник истины для разработки в Claude Code.

## 1. Суть

Polaris — открытый (MIT), self-hosted фоновый AI-агент. Работает круглосуточно на веб-сервере, помнит контекст, выполняет задачи в фоне, использует инструменты и присылает результаты. По духу близок к Claude Duet и ChatGPT Dots, но с открытым кодом, выбором провайдера моделей и видимой памятью.

Модель использования:
- Репозиторий открыт: любой может развернуть свой инстанс.
- Владелец инстанса (автор) и близкие пользуются им по паролю.

## 2. Что входит в v1

1. **Чат** с агентом (текст). История сохраняется.
2. **Фоновые задачи:** цель задаётся пользователем, агент выполняет шаги сам, статусы: в процессе / запланировано / готово / ждёт подтверждения.
3. **Утренняя сводка** (расписание настраивается).
4. **Память:** краткосрочная (контекст чата) и долгосрочная (факты, предпочтения). Пользователь видит, редактирует и удаляет записи.
5. **Инструменты v1:**
   - веб-поиск (Brave Search API, свой инструмент);
   - чтение веб-страниц;
   - браузер Playwright (headless, по запросу, с лимитом памяти);
   - заметки и напоминания;
   - файлы в Supabase Storage.
6. **Подтверждения:** действия с риском (отправка сообщений, платежи, удаление данных, внешние записи) выполняются только после подтверждения пользователем.
7. **Журнал действий:** каждый вызов инструмента логируется. Откат там, где возможен.
8. **Бюджет:** дневной и покомандный лимит токенов и денег, жёсткий стоп при превышении.
9. **Провайдеры моделей** с фолбэком:
   - порядок: первый — OpenRouter (или Gemini), последний — ChatGPT по OAuth;
   - при 429, таймауте или ошибке запрос уходит к следующему провайдеру.
10. **OAuth ChatGPT Plus/Pro:** есть всегда в ядре. Включается в настройках инстанса, помечено как личное использование на своей подписке. Одна подписка на инстанс. Ротации аккаунтов нет и не будет.
11. **Клиент:** нативное приложение iOS (Expo / React Native) и Android (APK). Установка на iPhone через бесплатный Apple ID.

**Не входит в v1:** управление рабочим столом (computer use), коннекторы (почта, календарь, Slack и т.д.), голос, команда агентов, маркетплейс скиллов, App Store публикация, Telegram-бот.

## 3. Стек

- **Сервер:** TypeScript, Node.js, Fastify. Деплой на Render (free) через Dockerfile или blueprint.
- **База и фон:** Supabase — Postgres, Auth (или пароль на инстанс, см. раздел 6), Storage, pg_cron, Edge Functions.
- **Пинг, чтобы Render не засыпал:** pg_cron в Supabase раз в 10 минут запрашивает `/health`.
- **Клиент:** Expo (React Native), TypeScript. Сборка iOS через GitHub Actions (macOS-раннер, unsigned .ipa), Android через EAS Build или APK в Actions.
- **Браузер:** Playwright (chromium headless), запускается по запросу, с таймаутами и очисткой.
- **Схема провайдеров:** единый интерфейс `ModelProvider`, реализации: OpenRouter, Gemini, Ollama, ChatGPT OAuth.
- **Линтинг и тесты:** ESLint, Prettier, Vitest.

## 4. Деплой и распространение

- **README с инструкцией:** Supabase-проект, переменные окружения, деплой на Render, пинг, первый вход.
- **Сборка iOS** через GitHub Actions: из репозитория получается unsigned `.ipa`.
- **Установка на iPhone:** Sideloadly (Windows) подписывает `.ipa` бесплатным Apple ID. Переподпись раз в 7 дней. Для автоматической переподписи — SideStore (фон, Anisette).
- **Резерв:** PWA-версия того же интерфейса на главном экране iPhone.

## 5. Безопасность

- Все ключи (API провайдеров, Brave, Supabase service key, OAuth-токены) хранятся только в переменных окружения Render / Supabase, не в коде.
- OAuth-токены ChatGPT шифруются перед записью в базу.
- Журнал действий не содержит секретов.
- Инструменты с риском требуют подтверждения (раздел 2, п. 6).
- Пароль инстанса хранится в виде хэша (bcrypt или argon2).
- Запрос к `/health` не раскрывает внутреннего состояния.

## 6. Аутентификация

- **v1:** один пароль на инстанс, сессии через httpOnly cookie. Вход для автора и близких.
- Supabase Auth как опция для multi-user (позже).

## 7. Схема данных (черновик)

- `conversations`: id, title, created_at
- `messages`: id, conversation_id, role, content, created_at
- `tasks`: id, goal, status, schedule, budget, created_at, updated_at
- `task_steps`: id, task_id, type, input, output, status, created_at
- `memory`: id, kind (fact | preference), content, source, created_at, updated_at
- `actions_log`: id, tool, args (без секретов), result_summary, status, created_at
- `approvals`: id, action, payload, status (pending | approved | rejected), created_at
- `provider_credentials`: id, provider, encrypted_token, expires_at
- `settings`: key, value

## 8. Открытые вопросы (не решено)

1. **Лимит памяти 512 МБ на Render (free).** Playwright может не влезть. Нужно решить: облегчённый браузер, внешний сервис браузера или отказ от браузера в v1.
2. **Веб-поиск через ChatGPT.** Не гарантирован: официального API нет. Поиск делается своим инструментом (Brave), не через подписку.
3. **Доступность OAuth-эндпоинтов ChatGPT.** Точный `CLIENT_ID`, URL бэкенда (`chatgpt.com/backend-api/codex`?) и заголовки (`chatgpt-account-id`?) не проверены по исходникам. Проверить перед реализацией.
4. **Условия OpenAI для публичного опенсорса с OAuth.** Оставить опцию с явным предупреждением или вынести в отдельный модуль, который не входит в дефолтную сборку. Решить до публикации.
5. **Пинг Render.** Работает, но не гарантирован правилами free-тарифа. Запасной план: платный Render или VPS.
6. **Расписание GitHub Actions** для iOS-сборки: нужен ли он вообще, или сборка только вручную.
7. **Точная схема провайдеров и фолбэка:** порядок, таймауты, поведение при частичном ответе.
8. **Anisette и SideStore:** адрес сервиса и стабильность автообновления подписи. Проверить на момент реализации.
9. **Имя:** выбрано `polaris-pl`. Проверить занятость на GitHub, npm и домене (автоматическая проверка в этой сессии недоступна).
10. **Лицензия:** MIT, подтвердить.

## 10. Вход ChatGPT (по образцу harness_v41)

Архив harness_v41 (оба присланных архива идентичны) делает вход так:
1. Кнопка «Подключить OpenAI» запускает процесс входа.
2. Пользователь проходит вход в браузере.
3. Кнопка «Проверить вход» проверяет статус.
4. Выбор модели из списка, по умолчанию `gpt-6-luna`.
5. Ошибка `model_not_found` означает, что модель недоступна для этого способа входа.

Что меняем для Polaris. Harness вызывает `codex login` как внешнюю программу, это работает только на Windows-ПК. Polaris работает на сервере и с телефона, поэтому:

- **Свой поток OAuth в сервере** (PKCE S256, `auth.openai.com/oauth/authorize`, обмен в `/oauth/token`), а не вызов CLI.
- **Вход без локального callback:** сервер отдаёт ссылку на авторизацию. После входа браузер перенаправит на `http://localhost:1455/auth/callback?code=...`, страница не откроется, это нормально. Пользователь копирует полный адрес из строки браузера и вставляет в Polaris. Сервер сам берёт `code` и делает обмен, используя сохранённый `code_verifier`.
- **Кнопки как в harness:** «Подключить ChatGPT», «Проверить вход», выбор модели.
- **Токены** шифруются и хранятся в `provider_credentials`. Обновление по `refresh_token`.
- **Статус входа** проверяет запрос к API, а не наличие файла.

Открытое: `CLIENT_ID` и redirect_uri должны совпадать с тем, что зарегистрировано у OpenAI для этого клиента. Это не проверено, см. раздел 8, п. 3. Если не совпадает, поток не заработает, и OAuth-провайдер остаётся опцией без реализации.
