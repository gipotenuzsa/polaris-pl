# Polaris ✦

Открытый (MIT) **self-hosted фоновый AI-агент**. Работает круглосуточно на вашем сервере, помнит контекст, выполняет задачи в фоне, пользуется инструментами и присылает результаты. Выбор провайдера моделей с автоматическим фолбэком, **видимая и редактируемая память**, подтверждение рискованных действий, журнал с откатом и жёсткие лимиты бюджета.

* Репозиторий открыт — любой разворачивает свой инстанс. Владелец и близкие входят по общему паролю.
* Клиенты: **Windows (.exe)**, iOS и Android (Expo / React Native), веб/PWA с того же сервера.
* Подробности замысла — в [`project.md`](project.md); принятые решения по открытым вопросам — в [`docs/DECISIONS.md`](docs/DECISIONS.md).

## Возможности (v1)

| | |
|---|---|
| **Чат** | история сохраняется; агент отвечает с вызовами инструментов, прогресс виден в диалоге |
| **Фоновые задачи** | цель → агент выполняет шаги сам. Статусы: запланировано · в процессе · ждёт подтверждения · готово (+ ошибка/отменена). Расписание: сразу, один раз, каждые N минут, ежедневно |
| **Утренняя сводка** | в заданное время: дела, задачи, напоминания, новости по вашим интересам из памяти |
| **Память** | краткосрочная — контекст чата; долгосрочная — факты и предпочтения, которые вы видите, правите и удаляете |
| **Инструменты** | веб-поиск (Brave), чтение страниц, браузер Playwright, заметки и напоминания, файлы в Supabase Storage |
| **Подтверждения** | удаление, перезапись, действия в браузере выполняются только после «Одобрить» |
| **Журнал действий** | каждый вызов инструмента (без секретов); откат там, где возможен |
| **Бюджет** | дневной и покомандный лимит токенов и денег, жёсткий стоп |
| **Провайдеры** | OpenRouter → Gemini → Ollama → **ChatGPT по OAuth** (всегда последний); при 429, таймауте или ошибке запрос уходит следующему |

## Быстрый старт

Нужен Node.js ≥ 22.

```bash
npm run install:all          # зависимости сервера и клиента
cp .env.example .env         # затем заполните: POLARIS_PASSWORD и ключ провайдера
npm run build:web            # веб-клиент → server/public
npm run dev:server           # http://localhost:8787
```

Без `DATABASE_URL` вне production сервер использует встроенную Postgres-совместимую базу (PGlite) в `./data`, а файлы кладёт на диск — Supabase для проверки не нужен.

**Попробовать вообще без ключей** — демо-модель, которая умеет вызывать инструменты:

```bash
node server/scripts/mock-llm.mjs 8799        # в отдельном терминале
# в .env:
#   OPENROUTER_API_KEY=demo
#   OPENROUTER_BASE_URL=http://127.0.0.1:8799/v1
#   OPENROUTER_MODEL=mock
```

Напишите в чате «запомни, что я люблю чай», «создай файл», «удали файл demo.txt» (появится запрос подтверждения), «создай задачу …».

### Windows-приложение (.exe)

Окно Electron с **локальным сервером внутри**: данные, ключи и файлы остаются на вашем ПК, облако не нужно. Вход автоматический. Из меню «Сервер» можно открыть файл настроек (ключи API), журнал и папку данных, а также подключить окно к удалённому серверу на Render.

Собрать (нужны Node ≥ 22 и интернет для скачивания Electron):

```bash
cd desktop
npm install
node node_modules/electron/install.js     # npm 11 не запускает install-скрипты сам
npm run dist                              # → desktop/release/
```

Результат: `Polaris-<версия>-portable.exe` (один файл, ничего не устанавливает), установщик `Polaris-Setup-<версия>.exe` и каталог `win-unpacked/Polaris.exe`. Готовые сборки даёт и GitHub Actions: **Actions → Windows (.exe) → Run workflow**. Для разработки: `npm run stage && npm start` в каталоге `desktop`.

При первом запуске создаётся `%APPDATA%\Polaris\polaris.env` — впишите туда `OPENROUTER_API_KEY` (или `GEMINI_API_KEY`, `OLLAMA_*`) и перезапустите сервер из меню. Exe не подписан цифровой подписью, поэтому SmartScreen может предупредить («Подробнее → Выполнить в любом случае»).

## Деплой: Supabase + Render

1. **Supabase.** Создайте проект. *Project Settings → Database → Connection string → Session pooler* — это `DATABASE_URL`. Ключ `service_role` (*Settings → API*) — это `SUPABASE_SERVICE_KEY`, `Project URL` — `SUPABASE_URL` (бакет `polaris-files` сервер создаёт сам, приватный).
   Миграции применяются автоматически при старте (`AUTO_MIGRATE=true`). Если предпочитаете Supabase CLI — `supabase db push` и `AUTO_MIGRATE=false`.
2. **Пароль.** `npm run hash-password -- "ваш длинный пароль"` → значение для `POLARIS_PASSWORD_HASH`.
3. **Render.** *New → Blueprint* → выберите репозиторий (используется [`render.yaml`](render.yaml) и [`Dockerfile`](Dockerfile)). Заполните секреты: `DATABASE_URL`, `POLARIS_PASSWORD_HASH`, ключи провайдеров (`OPENROUTER_API_KEY` и/или `GEMINI_API_KEY`), `SUPABASE_*`. `ENCRYPTION_KEY` и `CRON_SECRET` Render сгенерирует. После первого деплоя задайте `PUBLIC_URL` (адрес сервиса). Полный список переменных — в [`.env.example`](.env.example).
4. **Пинг, чтобы Render не засыпал.** Включите расширения `pg_cron` и `pg_net` (*Database → Extensions*), подставьте адрес сервиса и `CRON_SECRET` в [`supabase/optional/pg_cron_jobs.sql`](supabase/optional/pg_cron_jobs.sql) и выполните в SQL Editor. Раз в 10 минут запрашивается `/health`; раз в минуту `/internal/tick` запускает просроченные задачи, напоминания и сводку. Пинг не гарантирован правилами free-тарифа — запасной план: платный Render или VPS (тот же образ: `docker run -p 10000:10000 --env-file .env polaris`).
5. **Первый вход.** Откройте адрес сервиса — это и есть веб-версия (PWA). Введите пароль. Первый вход после «сна» Render занимает около минуты.

Память free-тарифа — 512 МБ: сервер укладывается (Node ограничен 384 МБ heap), а браузер Playwright по умолчанию выключен — см. «Браузер» ниже.

## Клиенты

| Платформа | Как получить |
|---|---|
| **Веб / PWA** | открыть адрес сервера; на iPhone: *Поделиться → На экран «Домой»*. Это же резерв, если iOS-сборка недоступна |
| **Windows** | `.exe` — см. выше |
| **Android** | **Actions → Android (APK) → Run workflow** → скачать `.apk` из артефактов и установить |
| **iOS** | **Actions → iOS (unsigned .ipa) → Run workflow** → скачать неподписанный `.ipa`, подписать **Sideloadly** (Windows/macOS) бесплатным Apple ID. Подпись живёт 7 дней; для автоматической переподписи используйте **SideStore** (понадобится Anisette-сервер — проверьте актуальный адрес) |

В приложении (iOS/Android) на экране входа укажите адрес сервера и пароль. Сессия хранится в защищённом хранилище устройства (на вебе — httpOnly-cookie).

Разработка клиента: `npm run dev:client` (Expo). Для веб-режима разработки добавьте в `.env` сервера `CORS_ORIGINS=http://localhost:8081`.

> Push-уведомлений на sideload-сборках iOS нет технически. Вместо них — вкладка «Уведомления», значки счётчиков и баннер, пока приложение открыто.

## Провайдеры моделей и фолбэк

Порядок: `PROVIDER_ORDER` (по умолчанию `openrouter,gemini,ollama`), затем **ChatGPT OAuth — всегда последний**. Провайдер без ключа пропускается. При 429, таймауте (`PROVIDER_TIMEOUT_MS`), 5xx, сетевой ошибке или пустом ответе запрос целиком уходит следующему; сбойный провайдер получает паузу (с учётом `Retry-After`). Частичных ответов нет — провайдеры вызываются без стриминга.

Стоимость: OpenRouter сообщает её сам; для Gemini и других — по таблице цен (`PRICES_JSON`, есть значения по умолчанию); подписка ChatGPT учитывается только токенами.

### ChatGPT по OAuth (Plus/Pro)

> ⚠️ Только для **личного использования на своей подписке**. Это неофициальный интерфейс (тот же, что использует Codex CLI): условия OpenAI могут его ограничивать, он может измениться без предупреждения. Одна подписка на инстанс, ротации аккаунтов нет и не будет. Провайдер выключен, пока вы сами его не включите.

В приложении: **Ещё → Настройки → ChatGPT (OAuth)**.

1. **Подключить ChatGPT** — сервер создаёт ссылку авторизации (PKCE S256), откройте её и войдите.
2. После входа браузер перенаправит на `http://localhost:1455/auth/callback?code=…` — страница не откроется, это нормально. Скопируйте **полный адрес** из строки браузера и вставьте в поле → **Завершить вход**. Сервер сам берёт `code` и обменивает его, используя сохранённый `code_verifier`.
3. **Проверить вход** — реальный запрос к API (а не проверка наличия файла). Ошибка `model_not_found` значит, что выбранная модель недоступна для этого способа входа — выберите другую. По умолчанию `gpt-6-luna` (как в harness_v41; список — `CHATGPT_MODELS`).
4. Включите переключатель «Использовать как запасной провайдер».

Токены шифруются AES-256-GCM (`ENCRYPTION_KEY`) и хранятся в `provider_credentials`; обновление по `refresh_token` (один запрос на всех параллельных вызовов; при 401 — принудительное обновление и один повтор).

## Инструменты, подтверждения и откат

| Инструмент | Риск |
|---|---|
| `web_search`, `read_url`, `browser_read`, `get_time` | безопасно (чтение; сетевые инструменты защищены от SSRF) |
| `note_*`, `reminder_*`, `memory_save/update/search`, `task_*` | безопасно, откатывается |
| `file_write` | новый файл — сразу; **перезапись — подтверждение**, прежняя версия сохраняется |
| `file_delete`, `note_delete`, `memory_delete`, `browser_act` | **всегда подтверждение** (файлы уходят в корзину) |

Рискованный вызов ставит агента на паузу: создаётся запрос в «Подтверждениях», действие **не выполняется**, пока вы не нажмёте «Одобрить» (в чате, во вкладке или в уведомлении). После решения агент продолжает с того же места — даже если сервер за это время перезапускался. Запросы без ответа через 48 часов (`APPROVAL_TTL_HOURS`) считаются отклонёнными.

**Журнал** (*Ещё → Журнал действий*): каждый вызов, аргументы без секретов (ключи, токены, пароли, JWT маскируются), результат и, где возможно, кнопка «Откатить».

Всё содержимое из интернета подаётся модели как недоверенные данные в явной обёртке; системный промпт запрещает выполнять инструкции из него — а опасные действия всё равно требуют вашего подтверждения.

### Браузер (Playwright)

`BROWSER_ENABLED=true` включает `browser_read` (JS-страницы) и `browser_act` (клики и ввод — только с подтверждением). Два режима:
* **внешний сервис** по CDP: `BROWSER_WS_ENDPOINT=wss://…` — рекомендуется для Render free;
* **локальный Chromium**: `docker build --build-arg WITH_BROWSER=1` (нужно больше 512 МБ) или `BROWSER_EXECUTABLE_PATH` (на Windows подойдёт Edge/Chrome).

Одна страница за раз, чистый контекст без cookie, без картинок/шрифтов/медиа, запросы во внутреннюю сеть блокируются, через минуту простоя браузер закрывается.

## Бюджет

*Ещё → Настройки → Бюджет*: дневной и покомандный лимит токенов и долларов (`0` — без лимита). «Команда» — одно сообщение в чат или один запуск задачи. Лимит проверяется перед каждым обращением к модели, `max_tokens` ограничивается остатком; при превышении агент **жёстко останавливается** и сообщает об этом. У задачи может быть собственный лимит.

## Безопасность

* Ключи — только в переменных окружения (Render/Supabase) или в локальном `polaris.env`; в коде и журнале их нет.
* Пароль инстанса — bcrypt-хэш; сессии — случайный токен, в БД только его SHA-256; httpOnly + SameSite=Strict cookie (Secure на https) либо Bearer для нативных клиентов; защита от CSRF по `Origin`; лимит попыток входа.
* OAuth-токены шифруются перед записью в базу; RLS включён на всех таблицах без политик.
* `/health` возвращает только `{"ok":true}`; `/internal/tick` требует `CRON_SECRET`.
* `read_url` и браузер не ходят во внутреннюю сеть (проверка адреса в момент соединения — защита от DNS-rebinding и редиректов).

## Устройство репозитория

```
server/     Fastify + TypeScript: API, агент, провайдеры, инструменты, планировщик (тесты: Vitest)
client/     Expo (React Native + web): iOS, Android, PWA
desktop/    Electron: Windows .exe с локальным сервером
supabase/   migrations/ — схема; optional/pg_cron_jobs.sql — пинг и тик планировщика
scripts/    build-web.mjs — сборка веб-клиента для сервера
docs/       DECISIONS.md — решения по открытым вопросам
```

Основные команды: `npm test` (сервер), `npm run lint`, `npm run typecheck`, `npm run build:web`, `npm run hash-password -- "пароль"`.

Схема работы: клиент → `POST /api/conversations/:id/messages` → агент в фоне (модель → инструменты → модель…) → клиент опрашивает диалог. Состояние прогона целиком в таблице `messages`, поэтому пауза на подтверждение и перезапуск сервера не теряют работу. Планировщик (`SCHEDULER_TICK_SECONDS` + внешний `/internal/tick`) атомарно забирает задачи, срабатывают напоминания, запускается сводка.

## Что проверено

Автотесты сервера (129): провайдеры и фолбэк, SSE/Responses API ChatGPT, OAuth/PKCE/обновление токенов (на моках), агентский цикл, подтверждения и откат, бюджет, задачи, расписание, утренняя сводка, SSRF, аутентификация, CSRF, CORS, реальный Chromium. Набор проходит и на встроенном PGlite (`npm test`), и на **настоящем PostgreSQL 18 через драйвер `pg`** — тем же путём, что работает с Supabase (`TEST_DATABASE_URL=postgresql://… npm run test:pg`; база должна быть в UTF8). Веб-клиент и Windows-приложение запускались и проверялись вживую против демо-модели; собранный сервер (`dist`) проверен запуском.

**Не проверялось** (нет доступа в среде разработки): реальный проект Supabase и Render, `Dockerfile` (Docker не был доступен), `pg_cron`/`pg_net`, сборки iOS и Android в GitHub Actions, вход в реальный аккаунт ChatGPT, реальные ключи OpenRouter/Gemini/Brave, отдельный запуск `Polaris-…-portable.exe` и установщика (проверялась распакованная сборка `win-unpacked`, из которой они собираются). Эти части написаны по документации и исходникам, но первый прогон на вашей стороне может потребовать мелких правок — особенно iOS/Android-workflows и OAuth ChatGPT.
